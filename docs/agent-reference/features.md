# Clipboard, emoji, voice — reference

Read this before touching `clipboard/`, `emoji/`, the voice input path,
or their panels. `AGENTS.md` carries the security invariants for these
features; this file carries the mechanics.

## Clipboard history (`clipboard/`)

- `ClipboardHistory` (pure, injectable clock): in-memory ring buffer, 50
  entries max, 1-hour lazy expiry, case-sensitive exact-match dedup
  (re-copy moves to top). Blank and >10k-char clips rejected. Deliberately
  not persisted.
- `SwipeKeyboardService` observes `ClipboardManager`
  (`OnPrimaryClipChangedListener`; the platform grants the default IME
  clipboard access even when hidden) → `KeyboardViewModel.addClip` →
  `KeyboardState.clipboard`. `ClipDescription.EXTRA_IS_SENSITIVE` clips
  never stored; only item text read (never `coerceToText`).
- 📋 key toggles `LayoutId.CLIPBOARD`; `ClipboardPanel.kt` renders
  outside the gesture `pointerInput`. Tap → `PasteClip` (returns to
  letters); long-press deletes. Paste → `KeyboardEffect.PasteText`,
  commits verbatim: never uppercased, no leading-space rules, no
  auto-proofread scheduling.

## Emoji suggestions (`emoji/`)

- `EmojiSuggester` (pure): matches the last few words before the cursor
  against a static keyword → emoji table, up to 8 emoji for the
  suggestion row atop the emoji panel. Offline HashMap lookups.
- Table: `app/src/main/assets/emoji_keywords_en.txt`
  (`keyword<TAB>emoji,emoji,...`, best first), generated by
  `tools/generate_emoji_keywords.py` from Unicode CLDR annotations.
  Hand-tuned aliases in the script's `ALIASES`. CLDR keys drop the VS16
  selector where the panel keeps it ("✈" vs "✈️") — the generator
  canonicalizes to the panel form, preserve that.
- Matching (`EmojiSuggesterTest`): last 3 letter tokens, last-two-word
  bigram first, exact then naive singular, most-recent-first, dedup,
  cap 8.
- Service owns the suggester → `KeyboardState.emojiSuggestions`;
  refreshed on panel open and on text change while open, cleared on
  switching away. Row hides when empty; panel height fixed. Suggestion
  taps commit via `KeyboardAction.InsertText` like grid taps.
- `EmojiPanel` is ONE scroll surface: a single `LazyVerticalGrid` holds
  suggestion block, "Categories" label, category bar, and sections; only
  the ABC/backspace bar is pinned. Category jumps depend on suggestion
  visibility — use `categoryJumpIndex(categories, hasSuggestions,
  index)` (pure, `EmojiDataTest`), never `categoryStartIndex` + hardcoded
  offset; keep the two in sync with the grid's item order.

## Voice input

- Mic key emits `KeyboardAction.ToggleVoice`; the **service** decides
  start/stop (permission + `SpeechRecognizer.isRecognitionAvailable`) and
  drives `VoiceState` (OFF/LISTENING/PERMISSION_REQUIRED/UNAVAILABLE) via
  ViewModel setters. While not OFF, key rows are replaced by `VoicePanel`
  and the container gesture loop swallows all touches — the
  `KeyboardGeometry` rects are stale and must not produce phantom text.
- `SpeechRecognizer` created lazily, destroyed on main thread;
  `onFinishInputView`/`onWindowHidden` cancel active sessions. Only final
  results committed (via `editor.commitWord` — leading-space and
  voice-proofread scheduling come free); partials only update the panel.
- Dictated text proofread with `ProofreadMode.VOICE` 2 s after commit,
  same debounce and never-clobber guard. ML Kit has **no custom-prompt
  hook** — `MlKitProofreader` holds a second client with
  `InputType.VOICE` (homophone-tuned). OpenRouter uses
  `ProofreadPrompt.VOICE_SYSTEM`/`VOICE_EXAMPLES`. `selectBackend`
  unchanged.
